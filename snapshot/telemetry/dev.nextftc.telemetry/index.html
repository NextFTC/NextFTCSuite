NextFTC Telemetry/dev.nextftc.telemetry

Package-level declarations

Telemetry, the entry point, which wraps a shared TelemetryRegistry. Log by name with Telemetry.log("Drive/Pose", pose), or hold a typed handle for the fast path: DoubleTopic, IntTopic, LongTopic, FloatTopic and BooleanTopic for numbers and booleans, and Topic<T> for strings, arrays, structs, and lists of structs. TelemetryTable groups related topics under a path, and TelemetryLoggable lets an object publish its own fields. For a type you don't own, register a TelemetryTypeHandler in TelemetryRegistry.handlers; Measure has one by default, which logs the base-unit value with its unit.

The registry stamps each value, sends it to every registered backend (or only those registered for a path prefix), and reports problems through a warning handler instead of throwing. A path keeps one type while a backend is registered, repeated numbers and strings are skipped unless a handle's keepDuplicates is set, and a handle made before any backend exists starts working when one is registered.

A handle can carry properties, the first being a unit that dashboards such as AdvantageScope show and convert: table.doubleTopic("wheelVelocity").withUnit("m/s"). They go out when the path is first published, as the properties of the NetworkTables announcement and as the metadata of the log entry, laid out the way WPILib logs NetworkTables topics. Values are strings, booleans, or finite numbers.

TelemetryBackend and TelemetryEntry are what a destination implements.
